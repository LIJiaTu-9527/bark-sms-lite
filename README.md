# 短信到 Bark

将安卓手机收到的短信推送到 iPhone 的 Bark。原生 Java 实现，无第三方运行库，APK 约 29 KB。最初面向小米 Note 3、Android 9 / MIUI 12 的备用机使用场景。

[下载最新安装包](https://github.com/LIJiaTu-9527/bark-sms-lite/releases/latest) · [v1.3 发布页](https://github.com/LIJiaTu-9527/bark-sms-lite/releases/tag/v1.3)

在发布页下载 `BarkSms-1.3.apk`，不需要下载源码压缩包。支持 Android 8.0 起，主要针对 Android 9 构建。
没有第三方运行库、广告、账号、统计或更新检查。无需 Root，无需设为默认短信应用。

1.2 版将设置界面从最近任务列表中排除；覆盖安装后首次打开应用，也会更新旧任务的标记。桌面图标和常驻通知保留。沿用原签名，可覆盖安装 1.0 / 1.1，保留设置及待发队列。短信前台服务和已有的一次性任务移除恢复逻辑保留，没有增加循环保活或定时联网。

1.3 版增加可随时修改的“分组名称”和“保存到 Bark 历史”开关，保留 1.2 的后台行为，可直接覆盖升级。默认组名仍为“短信”，历史保存默认关闭，不会在升级时自动开启。

## 安装与配置

1. 将 APK 传到小米手机，使用文件管理器打开安装。若系统提示，仅给当前安装来源授权。升级时直接覆盖，不要先卸载；装好后从桌面图标打开一次，让新版恢复服务并更新任务标记。
2. 在 iPhone 的 Bark 中允许通知，找到包含设备 Key 的推送地址。
3. 在安卓 App 中填写 `https://api.day.app/你的设备Key`，设置“分组名称”和“保存到 Bark 历史”，点“保存设置”。自建 Bark 也可使用 HTTPS 地址。
4. 点“测试推送”，确认 iPhone 确实收到通知。安卓显示“已送达 Bark 服务端”只代表服务端已确认，不能证明 iPhone 已显示通知。
5. 打开“启用短信转发”，允许接收短信权限。开启后会转发所有新收到的短信，包含发送号码、完整正文和短信接收时间。

不要把 Bark 地址里的设备 Key 发给别人。应用只向你配置的地址发请求，使用 Bark 公共服务时，短信仍会经过该服务端和苹果推送服务。

## 分组和历史记录

- 分组名称可随时修改，点“保存设置”后生效，无需重启。留空或只填空格会恢复默认组名“短信”。
- 新发送的短信（包括积压短信的重试）使用发送时已保存的组名和历史开关；已在发送中的请求可能仍使用旧设置。
- Bark 根据发送端提供的组名归组，无需提前创建。已经保存的历史消息不会自动迁移到新组。
- 想在 Bark 历史中保留消息，请打开“保存到 Bark 历史”后保存。此选项只影响之后发送的消息，以前未保存的通知不会自动补回。
- “测试推送”使用当前界面上填写的组名和历史开关；测试不会代替“保存设置”，正式短信使用已保存的设置。
- Bark 历史记录和安卓待发队列相互独立；发送成功后清除待发副本，不会删除 iPhone 上的 Bark 历史或系统短信中的原始短信。

## MIUI 12 后台设置

不同 MIUI 版本的菜单名称可能略有不同。

1. 在“设置 → 应用设置 → 应用管理 → 短信到 Bark”中，开启“自启动”。也可能位于“授权管理 → 自启动管理”。
2. 在此应用的“省电策略”中选择“无限制”。App 内“电池设置”可请求系统电池优化豁免，MIUI 自身的省电策略仍需单独检查。
3. 保留应用的常驻通知。1.2 版不在最近任务列表显示卡片，因此无需对卡片加锁。需要修改设置时，从桌面图标或通知进入。
4. 确保应用允许使用当前 Wi-Fi 或移动数据。关闭全局“超级省电”；如果有“锁屏后断开数据”或“锁屏清理内存”设置，避免它影响此应用。
5. 不要对应用点“强行停止”。重启后首次解锁一次；如果常驻通知没有恢复，手动打开应用检查。

1.2 版不提供最近任务卡片，避免手动划卡片时触发 MIUI 清理；这并不使应用获得系统级权限。关闭应用里的转发开关仍会停止服务并取消恢复，系统“强行停止”也会阻止恢复。MIUI 的全局清理仍可能直接终止应用且不给回调，或取消恢复任务，因此必须单独开启自启动和无限制省电，设置后验证实际效果。

程序使用前台服务、开机恢复和系统重试任务，但无法保证绕过 MIUI 的后台限制。手机必须保持开机、有短信信号并能联网。

## 在手机上验证

1. 亮屏时发一条普通短信，确认 Bark 收到。
2. 锁屏放置一晚，再发短信，确认仍能及时收到。这项最能验证 MIUI 后台设置。
3. 关闭安卓网络，保持手机短信信号，发一条短信；打开 App 确认“待发送”增加。恢复网络，确认自动补发。
4. 重启并首次解锁后，确认常驻通知恢复，再发一条短信。
5. 可再测试一条超过普通单条长度的短信，确认合并后的正文完整。
6. 升级后从桌面打开应用，确认转发已开启，按 Home 回到桌面。打开最近任务，确认没有“短信到 Bark”卡片；清理其他应用后等待约一分钟，再发一条短信，确认 Bark 收到。MIUI 的“一键清理”也需要单独实测。
7. 从桌面图标或常驻通知重新进入设置，确认可以正常打开。关闭转发开关后返回桌面，确认通知消失且不会自行恢复。
8. 填写组名“小米验证码”，开启历史保存并点“保存设置”，发送短信后检查 Bark 历史。再更改组名并保存，确认下一条进入新组；重新打开安卓应用，检查设置仍保留。

安装包已编译、完成 APK 签名与对齐校验，核心地址校验、HTTP 请求/响应、自定义分组及历史参数的 39 项主机检查已通过。这些主机检查不验证 Android 服务生命周期或设置界面。早期版本的用户反馈表明，MIUI 在划掉最近任务卡片时仍可能停止前台服务，因此 1.2 起排除最近任务卡片。最新版本的隐藏卡片、分组和设置持久化仍需真机实测；构建环境没有连接小米真机，也没有使用真实 Bark Key 验证端到端推送。

## 转发与数据行为

- 空闲时不轮询网络；保留低优先级常驻通知。网络请求只在测试或有待发送短信时执行。
- 长短信使用 Android 系统短信解析接口合并。同一条短信的重复广播会去重。
- 待发短信保存在应用私有数据库中。失败后从 30 秒开始递增重试，最长间隔 15 分钟；恢复网络时会尝试立即重发。系统休眠可能延后执行。
- 新短信不会被旧短信的失败重试挡住。积压短信会携带原接收时间，便于识别过期验证码。
- 服务端确认成功后，只删除此应用待发队列中的短信副本，不删除系统短信 App 中的原始短信，不改动用户文件或文件名。关闭转发会保留已经积压的待发短信；再次启用后继续发送。关闭期间新收到的短信不会补读。
- 最近状态只保留 20 条，不记录短信正文和 Bark Key；去重指纹保留约 7 天。系统备份已关闭。卸载或清除应用数据会移除设置和待发记录。
- 网络超时可能发生在服务端已经接收之后，重试有小概率造成重复推送；Bark 未提供此流程可用的端到端去重确认。
- 仅支持 HTTPS，使用系统证书校验；不绕过证书错误。旧系统遇到证书问题时，状态中会提示连接异常。

## 源码与构建

源码位于 `src/`，资源位于 `res/`。构建不需要 Gradle。

Windows 构建依赖：JDK 17、Android SDK Platform 28、Build Tools 35.0.0。
本次使用 Azul Zulu 17.0.17。构建工具下载在电脑缓存目录中，不会打包进 APK，也不需要装到手机上。

在此项目目录执行：

```powershell
.\build.ps1
.\tests\run.ps1
```

构建脚本默认从 `$env:USERPROFILE\.cache\bark-sms-toolchain` 查找依赖；也可以传入 `-Jdk`、`-AndroidJar` 和 `-BuildTools` 指定安装位置。主机测试额外使用 `org.json:json:20240303`，该测试库不会打包进 APK。

`.local/` 中保存本次生成的 APK 签名密钥与密码。请保留在自己的电脑上，不要分享。后续覆盖升级需要使用同一签名密钥；源码压缩包不包含密钥和密码。应用数据不含在源码中。
